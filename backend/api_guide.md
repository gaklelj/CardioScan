# CardioScan API Guide

Base URL: `http://<host>:6767`

## ADS1293: отведения I, II, III, V1 по TCP

Подключите компьютер к сети **CardioScan-ESP32**, пароль `12345678`.
Запустите локальный backend и в приложении выберите **WiFi → Начать сканирование**.
Backend подключается к `192.168.4.1:3333` как TCP-клиент (не WebSocket).
USB в предоставленной прошивке передаёт диагностические сообщения, а не ЭКГ.

Формат строки прошивки, завершающейся `\r\n`:

```text
timestamp_us,sequence,lead_I_raw,lead_II_raw,lead_III_raw,V1_raw,lost_samples
1200000,42,8388610,8388600,-10,8388620,3
```

I и II измеряются физическими каналами CH1 и CH2. III вычисляется в прошивке
как II − I; CH3 измеряет V1 относительно опоры Wilson. Приложение сохраняет
переданные значения без преобразования в мВ и показывает автомасштаб каждого
отведения. Частота SPI 1–4 МГц не является частотой дискретизации ЭКГ.
Оценка частоты измерений рассчитывается по времени и номерам кадров примерно
раз в секунду. Счётчики показывают отдельно пропуски номеров за подключение
и накопленные потери очереди прошивки — их нельзя складывать.

Событие `ecg_frames` содержит `frames` (массив объектов с `channels`,
`timestamp_us`, `sequence`, `lost_samples`), `sample_rate_hz`, `missing_samples`.
TCP-чтение поддерживает несколько строк в пакете и строки, разбитые между пакетами.
Старые шестиполевые кадры без V1 также поддерживаются. Bluetooth-подключение удалено;
доступны WiFi и USB (с совместимой прошивкой последовательного порта).
После запуска запись продолжается без десятисекундного ограничения. При остановке
или отключении устройства в истории сохраняются все принятые отсчёты, метаданные времени,
частота и подписи отведений. Превью отображает только конец записи.

Модель `ecg_ads1293.pt` получает I, II, III и анализирует последние 10 секунд.
V1 сохраняется и отображается, но не подаётся в эту модель. Клиент отправляет
только последние 11 секунд с временными метками, сервер выбирает окно 10 секунд.
Это не сокращает запись в истории. Пропуски в записи по-прежнему блокируют анализ.
Приём TCP не запускает модель на каждом пакете. Интерфейс отправляет окно данных
на анализ после накопления первых 10 секунд, затем не чаще раза в 2 секунды
при поступлении новых отсчётов. Одновременно выполняется один запрос; последний
результат остаётся видимым при пересчёте. После остановки выполняется итоговый
анализ. Опросник открывается отдельно и не блокирует результат ЭКГ.
Проверка пропусков при анализе относится к переданному окну, а счётчики и история
продолжают хранить пропуски всей записи.
Фото ЭКГ обрабатываются отдельной прежней моделью `best.pt`.

Проверки без оборудования:

```text
python -m unittest discover -s backend -p test_ecg_protocol.py
cd frontend
npm test -- --watchAll=false --runInBand --testPathPattern=ecgProtocol
npm run build:tauri
```

## REST

### GET /api/health

Проверка состояния сервера.

**Response 200**
```json
{
  "status": "ok",
  "model": "best_ecg_model.h5"
}
```

---

### POST /api/ecg/analyze

Анализ ЭКГ. Поддерживает три формата входа.

---

#### Вариант 1 — сырые точки (локальная модель)

**Request** `Content-Type: application/json`
```json
{
  "points": [0.1, 0.4, 0.9, 0.7, 0.3]
}
```

- `points` — массив float, любая длина (модель ожидает 1000 точек; если меньше — дополняется, если больше — обрезается)

**Response 200**
```json
{
  "class": "Normal",
  "confidence": 0.9321,
  "all": {
    "Normal": 0.9321,
    "Atrial Fibrillation": 0.0312,
    "Other": 0.0198,
    "Noise": 0.0087,
    "ST-elevation": 0.0054,
    "ST-depression": 0.0028
  }
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `class` | string | Предсказанный класс |
| `confidence` | float 0–1 | Уверенность модели |
| `all` | object | Вероятности по всем 6 классам |

Возможные значения `class`:
- `Normal`
- `Atrial Fibrillation`
- `Other`
- `Noise`
- `ST-elevation`
- `ST-depression`

---

#### Вариант 2 — изображение ЭКГ через multipart (Roboflow)

**Request** `Content-Type: multipart/form-data`
```
file=<бинарный файл изображения>
```

---

#### Вариант 3 — изображение ЭКГ через base64 (Roboflow)

**Request** `Content-Type: application/json`
```json
{
  "image": "<base64-encoded image>"
}
```

**Response 200** (варианты 2 и 3) — стандартный ответ Roboflow:
```json
{
  "predictions": [
    {
      "x": 320,
      "y": 240,
      "width": 100,
      "height": 50,
      "confidence": 0.87,
      "class": "ST-elevation"
    }
  ],
  "image": { "width": 640, "height": 480 }
}
```

---

#### Ошибки

| Код | Причина |
|-----|---------|
| 400 | Не передан ни `points`, ни `file`, ни `image` |
| 503 | Roboflow недоступен |
| 500 | Внутренняя ошибка сервера |

```json
{ "error": "описание ошибки" }
```

## WebSocket

Подключение: `ws://<host>:6767`
Протокол: Socket.IO

---

### Событие: `ecg_data` (клиент → сервер)

Передача одной точки в реальном времени (стриминг с датчика).

```json
{
  "channels": [0.52, 0.43, -0.31],
  "timestamp": 1710672000000
}
```

- `channels` содержит значения CH1, CH2 и CH3 ADS1293 в одном sample frame.
- Для совместимости сервер также принимает старое поле `value` как CH1.
- Сервер накапливает буфер из **1000 sample frames**
- При заполнении буфера автоматически запускает анализ и сбрасывает буфер

**Сервер эмитит в ответ:**

| Событие | Когда | Данные |
|---------|-------|--------|
| `ecg_point` | на каждый sample frame | `{ "value": float, "channels": [float, float, float], "timestamp": int }` |
| `ecg_analysis` | каждые 1000 точек | см. формат ответа модели выше |

---

### Событие: `ecg_batch` (клиент → сервер)

Передача пакета точек (оффлайн, например с ESP32).

```json
{
  "channels": [
    [0.1, 0.4, 0.9, 0.7, ...],
    [0.2, 0.3, 0.8, 0.6, ...],
    [-0.1, -0.4, -0.8, -0.5, ...]
  ]
}
```

Старый формат `{ "points": [...] }` остаётся поддержанным и трактуется как CH1.

**Сервер эмитит в ответ:**

| Событие | Данные |
|---------|--------|
| `ecg_batch` | эхо переданного пакета |
| `ecg_analysis` | результат анализа |
| `ecg_error` | `{ "error": "..." }` — если анализ упал |

---

## Примеры

### curl — сырые точки
```bash
curl -X POST http://localhost:6767/api/ecg/analyze \
  -H "Content-Type: application/json" \
  -d '{"points": [0.1, 0.5, 0.9, 0.4, 0.2]}'
```

### curl — изображение
```bash
curl -X POST http://localhost:6767/api/ecg/analyze \
  -F "file=@ecg_image.png"
```

### JavaScript — WebSocket стриминг
```js
const socket = io('http://localhost:6767')

// Отправка точки
socket.emit('ecg_data', { value: 0.52, timestamp: Date.now() })

// Получение результата анализа
socket.on('ecg_analysis', (result) => {
  console.log(result.class, result.confidence)
})
```

### Python — пакетный анализ
```python
import socketio

sio = socketio.Client()
sio.connect('http://localhost:6767')

sio.emit('ecg_batch', {'points': [0.1, 0.5, 0.9] * 333 + [0.1]})

@sio.on('ecg_analysis')
def on_result(data):
    print(data['class'], data['confidence'])
```
