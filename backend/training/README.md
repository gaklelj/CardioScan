# Обучение ЭКГ ADS1293

Из корня проекта:

```powershell
python backend/training/train.py --epochs 30
# Продолжить прерванное обучение с последней завершённой эпохи:
python backend/training/train.py --epochs 30 --resume
python -m unittest discover -s backend/training -p test_pipeline.py
# После обучения, для N x 3 .npy с известной частотой (пример: 500 Гц):
python backend/training/predict.py recording.npy --sample-rate 500
```

Зависимости: `backend/training/requirements.txt`. Подготовка автоматически читает
`data/DESTINATION` (PTB-XL) и `data/WFDB_ChapmanShaoxing`.
Результаты: `data/training_ads1293/`:

- `signals.npy`, `labels.npy`, `masks.npy`: данные и маски известной разметки;
- `manifest.csv`: источник, запись, пациент/ID, split и хеш сигнала;
- `dataset_summary.json`, `rejected.json`: состав данных и ошибки чтения;
- `best.pt`, `last.pt`: лучшая и последняя модели с состоянием оптимизатора;
- `history.jsonl`: метрики каждой эпохи;
- `test_metrics.json`: оценка лучшей модели на отложенном тесте после обучения.

## Вход и классы

10 секунд, I/II/III, приводятся к 100 Гц (1000 × 3). III вычисляется как II − I,
как в Arduino. Нормализация общая для каналов, с удалением постоянного смещения.
Ресемплинг использует полифазный фильтр против наложения частот.
В `ecg_three_lead.predict` передаются три массива каналов и **реальная частота ЭКГ**.
Частота SPI `ADS_SPI_HZ=1000000` не является частотой отсчётов ЭКГ.
Прошивка задаёт R2=5, R3=6; при остальных регистрах по умолчанию это
102400 / (4 × 5 × 6) ≈ 853.33 отсчёта/с (таблица 8 документации TI).
Конкретная частота зависит также от R1/режима АЦП и тактирования.
Для записанного потока её следует проверить по timestamp_us
и sequence; окна с потерянными отсчётами нельзя считать равномерными.

Выходы sigmoid: CD, HYP, MI, STTC, NORM, AF, NOISE.
Диагнозы могут сочетаться; softmax и единственный победивший класс не используются.
Из-за весов классов выходы сети не являются калиброванными вероятностями риска;
порог 0.5 не оценён как клинический порог.
PTB-XL даёт пять диагностических суперклассов и AFIB. Chapman обучает AF по
SNOMED CT 164889003; остальные выходы для него маскированы. Синусовый ритм
не приравнивается к нормальной ЭКГ. NORM обучается по PTB-XL.

NOISE обучается по аннотациям помех PTB-XL и искусственным повреждениям
(белый шум, дрейф, длительные помехи, плоский сигнал). Отсутствие аннотации
шума используется как слабая отрицательная метка с весом 0.2; это предположение,
а не экспертная оценка качества. При сильном искусственном шуме диагнозы маскируются.
Метрики NOISE являются оценкой на слабой/синтетической разметке.

## Разделение и ограничения

PTB-XL: folds 1–8 train, 9 validation, 10 test с разделением пациентов.
Chapman: стабильный hash ID записи, 80/10/10. В локальных заголовках нет ID
пациента, поэтому отсутствие пересечения пациентов Chapman не гарантируется.
Точные совпадения подготовленного сигнала удаляются до генерации шумов.
Validation выбирает лучшую эпоху по среднему AUROC диагнозов; test вызывается
после обучения. Early stopping: 6 эпох без улучшения, максимум 30.

Это исследовательская модель для трёх отведений. Работа на реальном ADS1293
и пороги решений требуют отдельной проверки на размеченных записях датчика.
`app.py` использует `backend/model/ecg_ads1293.pt` для запросов с тремя каналами.
Старая Keras-модель остаётся только для запросов с одним каналом, если доступна.
Веса загружаются один раз при запуске backend. После обновления весов нужен перезапуск.

## Экспорт и подключение

```powershell
python backend/training/export_model.py
python backend/app.py
```

Экспорт выбирает пороги по максимальному F1 на validation (не на test), сохраняет
`validation_thresholds.json` и переносит лучшую модель в `backend/model/ecg_ads1293.pt`.
Это исследовательские пороги, не калибровка вероятностей и не клинические пороги.
Путь можно переопределить через `ECG_THREE_LEAD_MODEL`.

REST `POST /api/ecg/analyze` и Socket.IO `ecg_batch` принимают:

```json
{"channels": [[0], [0], [0]], "sample_rate_hz": 853.3333333333}
```

Массивы в примере сокращены: требуется минимум 10 секунд на каждом канале.
Анализируется последнее 10-секундное окно. Вместо частоты можно передать `timing`:
одну тройку `[timestamp_us, sequence, lost_samples]` на каждый отсчёт. Интерфейс
передаёт эти данные автоматически для потока ADS1293. Пропуски/нарушения порядка
отсчётов и слишком короткие записи возвращают HTTP 400. Старые офлайн-записи без
частоты и временных меток нужно записать заново или передать с известной частотой.
Трёхканальный анализ выполняется после остановки записи; поток графика не блокируется
нейросетью. USB-кадры из шести полей также сохраняют временные метки.

Ответ содержит `model`, `labels`, `all`, `thresholds`, `analysis_channel`.
При NOISE диагнозы не показываются; NORM не показывается одновременно с патологией.
Старая модель риска не вызывается для новых оценок, поскольку не обучалась на них.
`GET /api/health` сообщает доступность трёхканальной, Keras- и YOLO-моделей отдельно.

### Следующие улучшения

- Собрать размеченную проверочную выборку с самого ADS1293: движения, плохой контакт,
  сетевые помехи и нормальные записи; текущий NOISE частично синтетический.
- Улучшать HYP: на текущем test average precision 0.479; проверить ошибки по записям,
  затем сравнивать архитектуру/аугментации на validation, не подбирать по test.
- Расширить совместимую разметку Chapman для остальных классов с явной проверкой
  соответствия кодов и доступности отрицательных меток.
- Отдельно оценить калибровку и качество по источникам; увеличение числа эпох само
  по себе не гарантирует улучшения (для текущего запуска выбрана эпоха 13).
